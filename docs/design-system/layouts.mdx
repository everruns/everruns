## The five zones

Every top-level entity screen composes the primitives in
[`apps/ui/src/components/layout/page-layout.tsx`](https://github.com/everruns/everruns/blob/main/apps/ui/src/components/layout/page-layout.tsx). Only the zone contents change from page to
page; no page invents a parallel shell.

1. **Breadcrumb**: `Group / Section / Name / Mode`. The group comes from the sidebar.
2. **Masthead**: a 40px icon tile with the gold 10% wash, the 28px title, a muted one-line
   description, an optional meta line, and the action cluster on the right.
3. **Control strip**: search on the left; status tabs and the view toggle on the right.
4. **Body**: the records, or the workspace of a detail page.
5. **Footer**: optional. It explains partial results or pagination, or links back.

The page has 24px padding and 24px between zones, on the dot grid.

  (`?tab=`). Non-primary tabs drop the config column and use the full width.

  "Not run") and opening a side sheet. They never become extra tabs.

  Nothing saves until Save changes.

  main column with a side rail. New detail screens use the workspace.

on the same tree and viewer from
[`apps/ui/src/components/files/`](https://github.com/everruns/everruns/blob/main/apps/ui/src/components/files/).
The [Knowledge pages](https://github.com/everruns/everruns/blob/main/knowledge/ui/knowledge-pages.md)
are the reference implementation.

- **One browser, many filesystems.** `FileBrowser` and `FileViewer` take a `FileSource` (list a
  folder, read a file, a download URL, optional writes). A source without writes renders
  read-only: no New, Edit, or Delete, and a lock on each file.
- **The tree loads one folder at a time.** Folders expand on demand; never page a whole
  recursive listing into the tree.
- **The selection is part of the address** (`?file=`), so search results and shared links open
  straight to a file.
- **Per-file controls sit in the viewer footer**, not in the tree. Extraction or sync state is
  a status dot in the viewer header; the tree shows a dot only when a file needs attention.
- **Section tabs are paths** on pages whose tabs are whole sections (Knowledge, Sandboxes):
  `/knowledge/{id}/sources`, with the shell as the tabs' layout.

## Reuse the page composition

Standard product routes use `PageContainer`, `PageBreadcrumb`, `PageMasthead`,
`PageControlStrip`, `PageMain` and `PageFooter`. List pages add `PageColumns` and `PageRail`
when facets are useful. Creation and editing pages reuse the masthead and section cards;
do not wrap an already card-based form in an extra card. Keep the same outer composition
while data loads or a query fails.

Reports and dense operational routes use the same primitives with full-width content as
needed. Chat and session workspaces retain their own reading and split-pane compositions.
The older `PageShell`, `PageHeader` and `PageBody` API is retired.

Settings uses its existing destination model in both presentations: a sidebar on large
screens and one destination selector on narrow screens. The form should be reachable in the
first viewport rather than following a full screen of navigation.

A form field consists of its label, control, optional hint and validation message. Keep
feature-specific draft state and validation in its owner; share the presentation. Changing a
control on an explicit-save page must not silently adopt autosave behavior. Pending, saved
and failed states must remain visible wherever autosave is used.
