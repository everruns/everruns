Everruns owns agent execution. A host supplies a coherent session authority
through `everruns::hosting::SessionHosting` and a claimed write capability through
`SessionEpoch`. Applications define ordinary `Agent` values and call the same
`Engine` and `Session` API regardless of the hosting implementation.

The hosting SPI is experimental. Framework has no dependency on a Cloudflare or
celld adapter. [Durable Object examples](/framework/durable-objects/) demonstrate
how an external implementation can use this boundary; they are source-only
references, outside the product publish set.

## Responsibilities

| Framework Engine | Hosting implementation | Application/deployment |
| --- | --- | --- |
| Planning, shared actor recovery and tool execution | Immutable session binding and transactional commands | Trusted Agent/build registry |
| Lifecycle hooks and finalized outcomes | Deduplicated input receipts and canonical journal | Retained code and Environment factories |
| Approval/client wait interpretation and context projection | Exclusive epochs, fenced storage and bounded snapshot reads | Workspace, compute, secrets and provider transport |
| Execution entry through `Engine::activate` | Independent wakeups, expiry discovery and activation retries | Authentication, authorization and operational recovery |

A hosting implementation must commit input, receipt and wakeup obligation before
acknowledging admission. Every execution mutation checks the same unexpired epoch
inside the authority transaction. Frontend readers reject mutations. Durable
hosts arrange activation independently of frontend connections and process-local
queues. An alarm or supervisor calls `Engine::activate(session_id)`; it never
implements a second planner or turn loop.

Registered builds and Environment references are immutable. Missing retained code
must produce visible suspension instead of falling back to the latest Agent.
A durable journal does not make tools, workspace files or external effects durable;
those services retain their own guarantees and idempotency requirements.

## Implementing a host

Depend on `everruns` with only the features the placement needs. The supported
storage/ownership paths are under `everruns::hosting::spi`: canonical events and
paging, actor leases/journal access, execution views, compaction checkpoints and
session values. `SessionHosting` and `SessionEpoch` describe the semantic contract.
Host implementations need no direct `everruns-core` or `everruns-contracts`
dependency, and do not construct the Engine runtime.

`SessionEpoch::backends()` supplies the low-level storage ports that Engine uses
internally. `HostBackends` is an implementation detail of writing a hosting
adapter, not Agent configuration. Its in-memory defaults are appropriate for
reconstructed definitions and explicitly volatile services. Replace every store
whose state your durability claim covers with the authority's fenced version.
Selecting individual stores through legacy Agent configuration is a separate,
weaker embedding path and does not establish coherent durable execution.

## Qualifying a host

Enable `hosting-conformance` in the host crate's **dev-dependencies**. The native
suite runs against a fresh test authority using the public Framework SPI:

```rust
async fn qualify(host: impl everruns::hosting::SessionHosting + Clone) {
everruns::hosting::conformance::authority(&host).await;
everruns::hosting::conformance::lease_expiry(&host).await;
everruns::hosting::conformance::engine_wait_recovery(host).await;
}
```

The scenarios check immutable bindings, admission retries/conflicts, bounded
snapshot paging, read-only frontend ports, exclusive epochs, lease expiry, stale writes,
Engine reconstruction, mixed approval/client waits and atomic retry handling.
The same suite runs against built-in memory/SQLite hosts and the independently
resolved DO reference. The feature is native test tooling; it does not add a
simulated provider to Wasm deployments or certify storage durability.

Also run deployment-specific failure tests: kill the executor or isolate after a
committed effect, allow no frontend requests during recovery, and require the
original admission to finish through an independent wakeup. Test lease expiry,
platform owner loss and retained-build failure according to the claimed failure
domain. The reference includes workerd, isolate and native-process harnesses;
local emulators alone do not establish production platform guarantees.
