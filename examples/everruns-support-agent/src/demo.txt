ANSWER

**Documented behavior** (docs.everruns.com):

The default `Engine::new()` keeps sessions in volatile memory — process exit loses them. To survive a restart you need the `local` feature:

1. `cargo add everruns --features local`
2. Build the Agent with `.local(LocalConfig::new(".everruns-data"))`, using the **same trusted data directory** each run.
3. Persist the typed `SessionId` yourself.
4. After restart: rebuild the Agent from trusted config, then

```rust
let engine = Engine::new();
engine.attach(session_id, build_agent()?).await?;
let resumed = engine.resume(session_id).await?;
```

`attach` is required because a new engine cannot infer the Agent snapshot; it rejects IDs absent from that Agent's local catalog, and `resume` returns a typed not-found error for unknown IDs. Note: a session only becomes durable after its first async operation (`run`, `inspect`, or a history page read).

Sources: https://docs.everruns.com/framework/session-history/ , https://docs.everruns.com/framework/persistence/

**Caveat, not guesswork-free:** the local profile supports one process at a time; for multi-worker restarts the docs point to the Platform instead.
