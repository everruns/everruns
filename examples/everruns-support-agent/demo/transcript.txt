ANSWER

**Documented behavior:** the default `Engine::new()` is volatile — process exit loses history, so resume only works within one engine's lifetime. To survive a restart you need the feature-gated local profile (`cargo add everruns --features local`).

Three steps in the new process:

```rust
let agent = build_agent()?; // same LocalConfig data dir, trusted config
let engine = Engine::new();
engine.attach(session_id, agent).await?;
let resumed = engine.resume(session_id).await?;
```

Key points from the docs:

- Persist the typed `SessionId` yourself; `resume` checks it against the catalog and returns a typed not-found error for unknown IDs.
- `attach` is required because a new engine can't infer the Agent; rebuild it from trusted config with the *same* data directory, or attach is rejected.
- A session becomes durable only after its first async operation (`run`, `inspect`, or a history page read).

Sources: https://docs.everruns.com/framework/session-history/ and https://docs.everruns.com/framework/persistence/

One caveat the docs state but your question doesn't cover: the local profile assumes one embedded process at a time — for multi-process or distributed restarts it points to the Platform instead.
