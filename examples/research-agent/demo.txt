# Idempotency
<a name="durable-execution-idempotency"></a>

Durable functions provide built-in idempotency for execution starts through execution names. When you provide an execution name, Lambda uses it to prevent duplicate executions and enable safe retries of invocation requests. Steps have at-least-once execution semantics by default. During replay, the SDK returns checkpointed results without re-executing completed steps, but your business logic must be idempotent to handle potential retries before completion.

ANSWER

- **Guarantee:** Durable execution replays only un-completed steps, so already-finished steps are not re-run; combined with an execution name (idempotency key), duplicate starts are rejected. (Temporal, AWS Lambda)

- **Failure window:** If a step is interrupted *before it completes* (crash, timeout), it may execute more than once — at-least-once semantics apply during that window. (Temporal, AWS Lambda)

- **Mitigation:** Make side-effect logic (e.g., payment calls) idempotent using idempotency keys or unique DB constraints; Temporal also offers an "at-most-once" mode (maxAttempts=1). (Temporal, AWS Lambda)
